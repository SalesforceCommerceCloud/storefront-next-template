# Security

## Purpose and boundaries

Trace trust boundaries and deployed response evidence. Combine final response headers with Playhouse diagnostics where runtime behavior matters. Never persist secret values; cite only redacted key names and locations.

## Investigation sequence

Map client/server boundaries, protected routes, sinks, and configuration before evaluating each rule. For CSP, identify the final document policy first, then correlate console, Inspector Issue, and blocked-request evidence across representative cells.

## Evidence and redaction

Redact credentials and personal data before writing any artifact. Playhouse console and diagnostic text can contain arbitrary application data; cite stable reason codes and sanitized URLs instead of copying full messages.

## Severity and blind spots

Dependency and infrastructure controls need current external evidence. A CSP diagnostic is not automatically a failure: the policy may be correctly blocking an optional or malicious request.
